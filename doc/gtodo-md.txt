1. Introduction                                        *gtodo-md-introduction*

|gtodo-md.nvim| is a Todo management plugin that brings a lightweight version
of GTD (Getting Things Done) to Neovim, using pure Markdown files.

The following files are automatically generated and managed:
- inbox.md      : A place to quickly dump unorganized tasks.
- todo.md       : Tasks categorized into Today, Next, Waiting, and Someday.
- done.md       : History of completed tasks (auto-sorted by month).
- cancelled.md  : History of cancelled tasks.

==============================================================================
2. Configuration                                      *gtodo-md-configuration*

After installing via your favorite plugin manager, call the setup function.
The default options are as follows:

>lua
    require("gtodo-md").setup({
      -- Directory to save task files
      data_dir = vim.fn.stdpath("data") .. "/gtodo-md",

      -- Whether to enable default keymaps
      use_default_keymaps = true,

      -- Picker to use for task searching ("auto" | "snacks" | "telescope" | "fzf-lua" | "builtin")
      picker = "auto",

      -- Prefix for default keymaps
      keymap_prefix = "<Leader>t",

      -- Minimum cooldown for overdue warning notifications (in seconds)
      due_notification_cooldown = 1800,

      -- Persist notification limitations across Neovim restarts
      due_notification_persist = true,
      
      -- Warning days for 'Waiting' tasks
      waiting_warning_days = 2,
      
      -- Enable warnings for 'Waiting' tasks
      enable_waiting_warning = true,
      
      -- Interval to check 'Waiting' task warnings (in seconds)
      waiting_warning_interval = 3600,
      
      -- Display progress bars at the bottom of project files
      enable_project_progress = true,
    })
<

*NOTE*: Even if you save files like `todo.md` under another name (e.g., `:w
backup.md`), the plugin's automated processes, keymaps, and checks will
always target the original task files located in `data_dir`.

3. Commands                                                *gtodo-md-commands*

The following user commands are provided:

:GtodoTodo
        Opens `todo.md` in a floating window.

:GtodoInbox
        Opens `inbox.md` in a floating window.

:GtodoDone
        Opens `done.md` (completion history) in a floating window.

:GtodoCancelled
        Opens `cancelled.md` (cancellation history) in a floating window.

:GtodoSort
        Manually sorts tasks in `todo.md` by due date and priority.

:GtodoSearch
        Executes an AND filter search using tags (+), contexts (@), or status.
        Supports rich integrations with Snacks, Telescope, and fzf-lua.

:GtodoQueue
        Opens the Queue view, displaying uncompleted tasks grouped by their
        due dates (Overdue, Next 7 Days, Later).

==============================================================================
4. Keymaps                                                 *gtodo-md-mappings*

Default keybindings when `use_default_keymaps = true`.
(Examples below assume the prefix is `<Leader>t`)

<Leader>tt  : Open `todo.md`
<Leader>ti  : Open `inbox.md`
<Leader>td  : Open `done.md`
<Leader>tc  : Open `cancelled.md`
<Leader>ta  : Add/Edit task interactively
<Leader>ts  : Search tasks
<Leader>tq  : Open the Queue view

gd          : Inside a markdown file, jump to the project file corresponding
              to the `+Project` tag under the cursor.

*Picker Actions*:
When using `:GtodoSearch` with Snacks, Telescope, or fzf-lua:
- `<Tab>`  : Multi-select tasks.
- `x`      : (Normal mode) Toggle completion of the selected tasks.
- `<C-x>`  : (Insert mode) Toggle completion of the selected tasks.

==============================================================================
5. Advanced Features                                       *gtodo-md-features*

*Statusline API*
You can display task counts on your statusline: >lua
    require('gtodo-md.api').get_statusline_string()
<
(See README for lualine-specific setup examples.)

*Dashboard API*
Integration with `snacks.dashboard` and `alpha-nvim` is provided: >lua
    require('gtodo-md.integrations.dashboard').snacks_section()
<

*Virtual Text & Highlights*
Task priorities `(A)`, `(B)`, and tags like `+project` and `@context` are
automatically syntax-highlighted. Due dates are augmented with virtual text 
showing relative days (e.g., "Tomorrow", "In 3 days").
